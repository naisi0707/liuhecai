# 刘伯温同构多租户资料论坛 — 设计规格

**日期：** 2026-07-22  
**状态：** 已确认；按模块门禁实现（见 plans）  
**参考站：** 311992.com（刘伯温论坛）信息架构；不搬运其付费内容与用户数据

## 1. 目标

构建一套可运营的多租户六合彩资料论坛平台：

- 前台信息架构与交互对齐刘伯温论坛（开奖、倒计时、资料列表、注册登录、充值指引、规则、客服）
- 超级管理端可一键开站（同模板：如至尊无上、神算子类站点）、绑定域名、生成代理账号
- 代理运营后台可改肤与运营（审帖、加币、客服、广告等）
- 各子站数据完全独立（`tenant_id` 隔离）

## 2. 非目标 / 约束

- **不抓取、不镜像** 原站付费资料正文、用户库、订单等专有数据；使用自建演示数据与运营自产内容
- 不对接在线支付；充值采用与原站类似的**人工确认加币**
- 首期不做像素级抄袭原站图片素材包；结构/模块一致，素材可替换为自有资源
- 首期不做一租户一库 / 一租户一部署

## 3. 架构总览

```
浏览器
  ├─ 站点域名     → Nuxt 3 前台（Host → tenant）
  ├─ 超管域名     → 超管后台
  └─ 代理后台域名 → 代理运营后台
         ↓
   Spring Boot 3 API（JWT 分身份）
         ↓
  MySQL 8（tenant_id） · Redis · 开奖拉取 Job
```

**多租户策略：** 单库 + 全业务表 `tenant_id`；请求 `Host` 查 `domains` 解析租户，写入 `TenantContext`，仓储层强制过滤。

## 4. 技术选型

| 层 | 选型 |
|----|------|
| 前台 | Nuxt 3 + TypeScript，移动优先，主题 CSS 变量按租户注入 |
| 管理端 | 同仓 Nuxt（超管 / 代理不同 layout），UI 可用 Element Plus |
| API | Spring Boot 3 + JWT（前台用户 / 代理 / 超管分 realm） |
| 持久化 | MySQL 8 + MyBatis-Plus |
| 缓存 | Redis（会话辅助、限流、开奖缓存） |
| 开奖 | 定时 Job 拉取公开源 + 失败可手工补录/覆盖 |

## 5. 数据模型（核心）

- **tenants** — 站名、状态、主题配置 JSON、客服微信/QQ、广告位配置
- **domains** — 域名、是否主域、验证/启用状态、归属 tenant
- **super_admins** — 超管账号
- **agent_accounts** — 代理账号（归属 tenant）
- **users** — 前台用户、金币余额（归属 tenant）
- **topics** — 资料帖（期号、玩法类型、价格、审核状态、正文）（归属 tenant）
- **orders** — 购帖订单
- **coin_logs** — 加币/扣币流水
- **recharge_requests** — 人工充值申请（待代理确认）
- **draw_results_global** — Job 写入的全局开奖（彩种、期号、号码、生肖属性）
- **draw_overrides** — 可选，租户对本期展示的手工覆盖

所有租户业务表必须带 `tenant_id`；跨租户查询仅超管统计类接口允许，且单独鉴权。

## 6. 功能模块

### 6.1 前台（按租户渲染）

- 首页：彩种 Tab（新澳门 / 香港 / 老澳门）、开奖号码+生肖、下期倒计时、公告条、资料列表
- 资料详情：未购买模糊/锁定；购买后扣币解锁正文
- 注册 / 登录 / 充值指引 / 规则 / 客服
- 主题：站名、Logo、主色、字体等来自租户配置

### 6.2 超级管理端

- 创建租户（同模板）
- 绑定域名；运营方自行 DNS 解析到平台入口
- 生成并展示代理账号密码（支持重置）
- 启停站点
- 配置开奖公共源（URL/解析策略占位 + 可扩展）
- 租户列表总览

### 6.3 代理运营端（运营级）

- 站名 / Logo / 主色 / 字体 / 公告
- 资料帖审核、上下架
- 确认充值并加币
- 客服联系方式、广告位
- 手工补录或覆盖本期开奖展示

## 7. 关键流程

1. **开站：** 超管建租户 → 填域名 → 用户解析 DNS → 生成代理账密 → 代理登录改肤  
2. **充值：** 用户提交申请或按指引联系客服 → 代理确认 → `coin_logs` + 余额增加  
3. **购帖：** 余额校验 → 事务扣币 → 写订单 → 解锁正文  
4. **开奖：** 定时 Job 拉公开源 → 写全局结果 → 前台展示；失败保留上期并支持手工补

## 8. 安全与错误处理

- 业务查询强制租户隔离；禁止仅靠前端传 `tenantId` 作为信任源
- 购帖/加币使用数据库事务 + 余额乐观锁（或等价原子更新），防重复扣与超卖
- 域名未绑定 / 租户停用 → 友好错误页
- 开奖拉取失败 → 日志/可观测 + 手工补录路径
- 管理端与前台 JWT 分签发与权限；代理不可开站、不可操作其他租户

## 9. MVP 验收标准

1. 超管可创建至少 2 个租户并绑定不同域名，用户与帖子数据互不串扰  
2. 代理可改肤、审帖、加币，前台刷新后生效  
3. 用户注册 → 充值确认 → 购帖解锁全流程可演示跑通  
4. 至少一个彩种可自动拉取开奖；失败时可手工补录并在前台可见  
5. 前台信息架构对齐刘伯温模块结构（非要求盗用原站静态资源）

| 项 | 选择 |
|----|------|
| 产品深度 | 可运营系统 |

| 前端 | Nuxt + 独立 API |

| 视觉 | 结构对齐刘伯温；多租户白标由代理改肤 |
| 子站数据 | 完全独立 |
| 代理权限 | 运营级 |
| 开奖 | 对接公开源 + 可手工补 |
| 多租户实现 | 单库 + tenant_id |
